# UI/UX 최종 감사 (Phase 6)

브라우저 preview에서 실제 화면을 실행해 감사하고, 발견한 문제를 실제로
수정했다. 소스만 읽고 판단하지 않았다.

## 주요 개선 (P0/P1)

| 화면/영역 | 개선 |
| --- | --- |
| 최초 실행 | 3단계 온보딩 다이얼로그 추가 — 앱 용도/API·인터넷 불필요/로컬 저장을 설명. `<dialog>` 요소로 focus trap·Escape 기본 지원, 완료 상태를 서버 config에 저장해 반복 노출 안 함, 설정에서 "처음 안내 다시 보기"로 재열람 |
| 채점 진행 | 단순 "채점 중…" → Offline Core 실제 처리 순서 문구 3단계("답안 구조 확인 → 문법·표현 분석 → 점수·개선 방향 정리"). 처리가 빨리 끝나면 억지 대기 없이 결과 표시, 가짜 진행률 없음 |
| 채점 실패 | "오류: ..." → "채점하지 못했어요: ... — 작성한 답안은 그대로 남아 있어요. 다시 시도해 주세요." (답안 안전 명시 + 다음 행동 안내) |
| 기록 | 각 행에 PDF·삭제 버튼 추가. 삭제는 확인 후 해당 1건만 제거(다른 기록 안전 안내), history·dashboard 자동 갱신 |
| 작성 중 답안 | localStorage에 더해 서버 draft(800ms 디바운스)로 이중 보존 → 강제 종료·저장소 초기화에도 복구. 로드 시 "작성하던 답안을 불러왔어요" |
| 설정 | "백업 및 데이터 관리" 섹션 신설 — 백업 생성/목록/복원/전체삭제. 전체 삭제는 확인 문구("모두 삭제") 입력 요구 + 자동 안전 백업 |
| Build a Sentence | 문항 8→15개(난이도 3단계). 진행 상황("완료 N/15"), 정답 설명(문법 포인트), "다음 문제" 버튼, 난이도·문법 태그 라벨 |

## 문구 정리 (마스터 스펙 30장)

- "구버전" → "이전 기준" (기록 legacy 배지)
- "초안 비움" → "비웠어요", "자동저장 완료" 유지하되 실패 시 "임시 보관됨 (이 창에만)"
- 결과/오류 문구에서 비난·불안 표현 배제, 존댓말 일관
- 온보딩에 "점수는 연습용 예상치이며 공식 TOEFL 점수가 아니에요" 명시
- 기술 용어(엔진/스키마/Provider/Shadow)는 상세·개발자 영역에만, 일반 화면은 쉬운 표현

## 접근성

| 항목 | 상태 |
| --- | --- |
| 온보딩 다이얼로그 focus trap·Escape | `<dialog>` 네이티브 지원, autofocus 시작 버튼 |
| 기록/백업 버튼 accessible name | `aria-label` 부여 |
| Build a Sentence 키보드 조작 | 모든 조각/이동/제거가 `<button>` — Tab+Enter/Space 동작 (드래그앤드롭 미사용) |
| 상태 알림 | `role="status"` + `aria-live="polite"` (draft, 백업, 삭제, BAS 진행) |
| reduced motion | `@media (prefers-reduced-motion: reduce)`로 모든 비필수 애니메이션 제거 |
| 삭제 확인 | 전체 삭제는 문구 입력 + 명시적 버튼 (단순 1클릭 아님) |

## viewport

375px(mobile)·desktop에서 실제 확인 — 가로 overflow 0(`scrollWidth === clientWidth`),
history-row/backup-row/onboarding-dialog 개별 요소 overflow 없음. 온보딩
다이얼로그는 `width: calc(100vw - 48px)`로 좁은 창 대응.

## 검증 방식

- 브라우저 preview 클릭 시뮬레이션: 온보딩 완료→저장, BAS 정답 제출→설명·다음
  문제·진행 갱신, 백업 생성(기록 76건)→목록, 복원
- 콘솔 에러 0건, 실패 네트워크 요청 0건
- 패키징 앱에서는 API 레벨 재확인 (전체 클릭 플로우의 네이티브 창 육안
  렌더링은 수동 검증 항목 — `docs/release-candidate-test-report.md`)
