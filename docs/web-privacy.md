# 웹(Hosted/Self-host) 개인정보 처리 — 데스크톱과의 차이

`docs/privacy.md`는 데스크톱 앱(로컬 저장) 기준이다. 이 문서는 **브라우저로
접속하는 hosted/self-host 실행**에서 무엇이 달라지는지 정확히 구분한다.
데스크톱 앱과 hosted web은 데이터 흐름이 다르므로, 아래 문구는 서로 바꿔
쓸 수 없다.

## 핵심 차이

| | 데스크톱 앱 | Hosted/Self-host 웹 |
|---|---|---|
| 답안 처리 위치 | 이 기기 안(로컬 FastAPI 서버) | **채점을 위해 이 웹 서버로 전송됨** |
| 저장 위치 | `~/Library/Application Support/...` 등 로컬 파일 | 서버의 SQLite (배포 방식에 따라 영속적이거나 컨테이너 재시작 시 사라짐) |
| 외부 AI 전송 | 사용자가 직접 켜기 전까지 없음 | **동일 — 클라우드 AI는 기본 비활성이며, 켜기 전까지 외부로 전송되지 않음** |
| 다른 사용자와 데이터 격리 | 해당 없음(1인 기기) | 공개 hosted 배포에서는 **계정 시스템이 없으므로 세션/기록 격리가 보장되지 않을 수 있음** |

## 정확한 문구

**틀린 표현(hosted web에는 쓰면 안 됨):**
> "답안은 절대 기기를 벗어나지 않습니다."

이 문장은 **데스크톱 앱에서만** 참이다.

**맞는 표현(hosted web):**
> 웹 체험판에서는 답안이 채점 처리를 위해 이 서버로 전송됩니다.
> 기본 분석(Offline Core)은 외부 AI API 없이 이 서버 안에서 처리됩니다.
> 클라우드 AI는 기본적으로 꺼져 있으며, 사용자가 직접 켜지 않는 한 답안이
> OpenAI·Claude·Gemini 등 외부 AI 서비스로 전송되지 않습니다.
> 현재 공개 체험판은 계정 기능 없이 제공되며, 민감한 개인정보나 실명이
> 포함된 답안은 입력하지 않는 것을 권장합니다.

## 저장 지속성 (배포 방식에 따라 다름)

- **로컬 볼륨 없이 Docker 실행** — 컨테이너를 재생성하면 SQLite 데이터가
  사라진다(ephemeral). `docs/hosted-web-deployment.md`의 볼륨 마운트 안내 참고.
- **볼륨을 마운트한 경우** — 재시작해도 유지되지만, 여러 사용자가 같은
  컨테이너를 공유하므로 **한 사용자의 기록이 다른 사용자에게 보일 수 있다**
  (계정/세션 분리가 구현되지 않았기 때문). 공개 다중 사용자 배포에는
  현재 권장하지 않는다.
- 운영자가 직접 이 정책을 UI에 명확히 공지해야 한다.

## 로그

- `desktop/server_manager.py`와 동일하게, hosted 배포에서도 요청 바디(답안
  원문)는 로그에 남기지 않는 것을 권장한다. `docs/hosted-web-deployment.md`의
  `uvicorn --no-access-log` 권장 설정 참고(Docker 기본 CMD에 이미 적용됨).
- 운영자가 리버스 프록시(nginx 등)를 앞에 둘 경우, 프록시 access log에
  요청 바디가 남지 않는지 별도로 확인해야 한다(FastAPI 서버 자체는 바디를
  로그에 남기지 않지만, 프록시 설정은 이 프로젝트 범위 밖이다).

## 삭제

- 데스크톱과 달리, hosted 배포에는 현재 사용자별 "내 데이터만 삭제" 기능이
  없다(계정 시스템 없음). 컨테이너/볼륨을 통째로 삭제하는 것이 유일한
  전체 삭제 방법이다 — 이는 운영자만 수행할 수 있다.
- 공개 다중 사용자 서비스로 발전시키려면 계정별 export/delete가 필요하며,
  이는 아직 구현되지 않았다(`docs/privacy.md`에도 동일하게 명시).
